Change sets

Example session — not live QGIS data. A design mockup for a QGIS plugin concept. Colour identifies the datum, not the severity: two rows sharing a colour are in the same reference frame and need no shift between them. Texture carries the state of the shift.
One kind of record. The project is an object with state, exactly like a layer — so changing the project CRS is not an event with twelve effects, it is one more state change that the others point at. A change set is just the id shared by everything written in one action; the two buttons above are the same edges traversed two ways.
The originating object is derived, not recorded. A layer's state is a function of its own CRS and the project's. If a layer changed while its own inputs did not, the change came from upstream — so nothing has to assert a cause. Rows are written only where state actually differed, which is why site_notes.gpkg never appears despite the project CRS moving under it, and why a summary count is worth reading.
